Teaching Laya Persian

Fine-tuning a System 1 decision model and racing it against a closed-source API.

Ever read Daniel Kahneman? LLMs have the same split. System 2 is the big autoregressive model. it reads your prompt, generates tokens one at a time, reasons, and answers. Powerful but slow and expensive, a full pass over every response for every question. System 1 is the fast reflex. given a situation and a concrete question, it fires back a decision now, with a probability attached.

And most real products are drowning in System 1. Was this message spam? Does the customer want a refund? Is this review positive? Every one of those deserves an instant, calibrated answer routing each through a generative workflow is overkill.

What makes Laya different from a normal classifier

The model I fine-tuned is Laya's multilingual checkpoint, from convaiinnovations/laya. It's a non-autoregressive System 1 decision model: it never generates text a state plus typed questions go in, typed answers with calibrated probabilities come out in a single forward pass (~33 ms), nothing to parse. Its encoder is a mmBERT 22 layers, 256k vocab, bidirectional attention, and a context window up to 8k tokens where classic BERT tops out at 512. That's the boring part, honestly. The interesting difference is how it answers, so let's line the two up side by side:

Classic classifier

The output space is fixed at design time. Train a sentiment classifier and, as the developer, you already know before writing any code that it will only ever output positive / negative / neutral so you just wire that head into the network while designing it. One head, one job: want a second task, train a second model.

Laya

Can't have a fixed output head, because it's built to be universal. It has to understand the state through language modeling itself and then pick from whatever options the caller sent a list that could be arbitrarily large or descriptive. There's no pre-wired head for positive/negative/neutral, because there's no knowing what you'll ask.

That one design decision buys two things:

  • One model, any question. At runtime you send a state plus any set of questions in three flavors choice (pick from any list of options you provide), score (rate over named levels), and noul (plain yes/no). The same checkpoint fine-tuned on Persian customer service handles all three, because the format is learned, not wired into a head.
  • It can't hallucinate labels. It's architecturally forced to choose only among the options the user sent and assign each one a probability nothing outside the list can come out of the wire format. The answer can still be wrong (training data is never perfect), but it can't invent an option you never offered.

Training is RLCD-style contrastive learning: the model is rewarded not just for the right label, but for calibrated probabilities its distribution is scored against the gold distribution, so "85% sure" actually means 85%.

The Farsi dataset

I took four decision-making domains, converted them to the typed-decisions format state, questions, and a gold that carries soft distributions (e.g. {false: 0.88, true: 0.12} instead of a bare label) and machine-translated the whole thing to Persian: about 48k training cases and roughly 10k held-out test cases.

Fine-tuning

Starting from the multilingual Laya checkpoint (convaiinnovations/laya), each domain got its own fine-tuned model 4 epochs with the standard RLCD trainer and all are up on Hugging Face:

  • Retail shopping: mo-shadfar/laya-fa-retail-shopping
  • Sentiment / moderation: mo-shadfar/laya-fa-sentiment-moderation
  • Spam detection: mo-shadfar/laya-fa-spam-detection
  • Intent routing: mo-shadfar/laya-fa-intent-routing

The takeaway

For the reflex layer of an LLM product spam, intent routing, sentiment, any "answer now" question a small fine-tuned encoder you own beats a closed-source API on accuracy and destroys it on latency. The model is public; go fine-tune it on your own domain.

Try it yourself

This whole script is the demo: pull the fine-tuned intent-routing model from Hugging Face and ask it one real question from the test set. First run downloads the weights (~600 MB), after that it's cached.

import laya

MODEL = "mo-shadfar/laya-fa-intent-routing"

STATE = "مبلغ استرداد در حساب من نمایش داده نمی‌شود."

QUESTIONS = {
    "support_intent": {
        "type": "choice",
        "instructions": "کدام قصد پشتیبانی با پیام مشتری مطابقت بیشتری دارد؟",
        "criteria": {
            "Refund_not_showing_up": "عدم نمایش مبلغ استرداد",
            "card_not_working": "کارت کار نمی‌کند",
            "pending_top_up": "شارژ در انتظار",
            "virtual_card_not_working": "کارت مجازی کار نمی‌کند",
            "contactless_not_working": "پرداخت بدون تماس کار نمی‌کند",
        },
    }
}

# gold label for this is: Refund_not_showing_up

def main():
    agent = laya.load(MODEL)
    answers = agent.predict(STATE, QUESTIONS)["answers"]
    a = answers["support_intent"]
    print("pred:" + a["choice"] + "  confidence:" + str(a["confidence"]))


if __name__ == "__main__":
    main()

The message is Persian and the five options come straight from the data. The correct label for this row is Refund_not_showing_up, so the printout should read pred: Refund_not_showing_up with a confident probability attached. Swap MODEL for any of the other three fine-tuned repos and the same lines work unchanged.
